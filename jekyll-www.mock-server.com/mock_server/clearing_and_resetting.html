MockServer has the following internal state:

  • recorded requests
  • active expectations
  • recorded expectations
  • logs

State can be cleared from MockServer selectively:

  • use type to select which type of state to clear, supported values are: all, log, expectations
  • use a request matcher to clear matching items
  • use an expectation id to clear matching items

What each type affects: the type parameter is important for memory management. expectations clears only the configured expectations — it does not clear the recorded request / event log. On a long-running instance the request log grows with every request, so clearing expectations alone will not free that memory. To free memory held by accumulated log entries, use log or all, or perform a full reset with PUT /mockserver/reset.

Operation Expectations Request / event log
clear?type=expectations cleared kept
clear?type=log kept cleared
clear?type=all (the default when type is omitted) cleared cleared
PUT /mockserver/reset cleared cleared

Note: a request matcher or expectation id narrows clearing to matching items; reset always clears everything and ignores any matcher. An empty request matcher (request() or {}) narrows nothing: it clears everything of the chosen type, including DNS, binary and not(...) expectations, just like an empty body.

How clearing works: when logLevel is INFO or lower (the default), cleared log entries are soft-deleted rather than physically removed. This means:

  • Verification works correctly — the verify endpoint ignores cleared entries, so verifying a request after clearing will behave as if the logs were fully removed
  • Retrieve works correctly — the retrieve endpoint for requests, recorded expectations, and log messages filters out cleared entries
  • UI may still show cleared entries — the UI can display soft-deleted entries (marked as deleted) to help debug issues

If you want cleared log entries to be physically removed from memory, set the log level to WARN or higher.

new MockServerClient("localhost", 1080).clear(
    request(),
    ClearType.LOG
);
var mockServerClient = require('mockserver-client').mockServerClient;
mockServerClient("localhost", 1080)
  .clear({}, 'LOG')
  .then(
    function () {
      console.log("cleared recorded requests and logs that matches request matcher");
    },
    function (error) {
      console.log(error);
    }
  );

Clearing by namespace (multi-tenancy)

When multiple teams or test suites share one MockServer instance, expectations can be scoped to a namespace (tenant) so each owner can clean up only its own expectations without disturbing anyone else's. An expectation with no namespace (the default) is global and is matched regardless of any request namespace.

Add ?namespace=<name> to PUT /mockserver/clear to clear only that namespace's expectations (the event log is not namespaced, so it is left untouched even with type=all). The namespace can also be supplied as a header instead of the query parameter — see matchNamespaceHeader — the query parameter takes precedence when both are present.

new MockServerClient("localhost", 1080).clearByNamespace("team-checkout");
curl -v -X PUT "http://localhost:1080/mockserver/clear?type=expectations&namespace=team-checkout"

Or with the configured namespace header instead of the query parameter:

curl -v -X PUT "http://localhost:1080/mockserver/clear?type=expectations" \
  -H "X-MockServer-Namespace: team-checkout"

To create an expectation scoped to a namespace in the first place, see withNamespace(...) on the Java client.

 

Clearing by metadata or unused expectations

You can clear only the expectations whose metadata matches, or only the expectations that have never matched a request, for example to remove mocks a test suite no longer uses. Like a namespace clear, these remove expectations only and leave the event log untouched, even with type=all.

Add these query parameters to PUT /mockserver/clear:

  • metadataKey=<key>: the expectation's metadata has this key. Add metadataValue=<value> to also require the value. The value matches a stored text equal to it, or a stored JSON value equal to it read as JSON: metadataValue=42 matches both the number 42 and the text "42", and metadataValue=%22team-a%22 also matches the text team-a.
  • metadataJsonPath=<JSONPath>: the JSONPath, applied to the metadata object, selects something, for example $.tags[?(@ == 'smoke')].
  • unmatched=true: the expectation has not matched any request since it was created or last changed. Each MockServer instance keeps its own count.

When you combine these with each other, with namespace, or with a request matcher or expectation id in the body, an expectation is cleared only if it matches all of them.

To protect you from clearing everything by mistake, an empty value (for example metadataKey= when a script variable is unset), or unmatched=false on its own, is rejected with 400 Bad Request and nothing is cleared. Parameter names are not case-sensitive. A parameter given twice, or one whose name starts with metadata or unmatched but is not one of the parameters above (such as metadata_key), is also rejected. Any other unknown parameter is ignored, as on every MockServer endpoint, so check the spelling before you clear: a misspelling such as metaKey=owner is ignored and the clear is not filtered. Values are used exactly as given, so a value starting with ! or ? is not treated as a "not" or "optional" matcher.

URL-encode every value: send % as %25, + as %2B (a plain + means a space), & as %26 and # as %23 (HTTP clients drop everything from a plain #, so metadataKey=env#prod would be sent as metadataKey=env). With curl, -G --data-urlencode does this for you. A query string that cannot be decoded, such as metadataValue=100%, is rejected with 400 and nothing is cleared. So is an empty namespace= on clear.

new MockServerClient("localhost", 1080).clearByMetadata("owner", "team-checkout");

To clear every expectation that has a key, whatever its value, use clearByMetadataKey("owner"). A null value is refused rather than read as "any value".

Or with a JSONPath on the metadata:

new MockServerClient("localhost", 1080).clear(
    null,
    ExpectationFilter.expectationFilter().withMetadataJsonPath("$.tags[?(@ == 'smoke')]")
);
var mockServerClient = require('mockserver-client').mockServerClient;
mockServerClient("localhost", 1080).clearByMetadata("owner", "team-checkout");
// any value for the key: clearByMetadataKey("owner")

With a JSONPath, let curl encode it:

curl -v -X PUT -G "http://localhost:1080/mockserver/clear" \
  --data-urlencode "type=expectations" \
  --data-urlencode "metadataJsonPath=$.tags[?(@ == 'smoke')]"
