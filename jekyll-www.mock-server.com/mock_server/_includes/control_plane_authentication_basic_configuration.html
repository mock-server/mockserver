Accept HTTP Basic credentials (a username and password) for control plane interactions (i.e. create expectations, clear, reset, verify, retrieve, stop, etc). The users are configured with controlPlaneBasicAuthenticationCredentials or controlPlaneBasicAuthenticationUsersFile.

Basic credentials are only accepted over HTTPS: a request that sends them over plain HTTP is refused with a 401, because anyone on the network path could read the password, and a plain-HTTP 401 never asks a browser for a password. After 5 wrong passwords from one address, that address must wait (1 second, then 2, 4, ... up to 60 seconds) before new credentials are checked again. A user who already logged in successfully is not locked out. Clients that reach MockServer through one shared address, such as a NAT gateway or a load balancer that hides client addresses, share that wait, so one client guessing passwords slows down new logins for all of them.

Basic is an alternative to the other control plane authentication methods: when it is enabled alongside mTLS, JWT or OIDC, a request is accepted if it has valid Basic credentials or it passes the other enabled methods. The user name is recorded as the principal in the control plane audit log.

This setting is fixed at startup: PUT /mockserver/configuration cannot change it.

Type: boolean Default: false

Java Code:

ConfigurationProperties.controlPlaneBasicAuthenticationRequired(boolean controlPlaneBasicAuthenticationRequired)

System Property:

-Dmockserver.controlPlaneBasicAuthenticationRequired=...

Environment Variable:

MOCKSERVER_CONTROL_PLANE_BASIC_AUTHENTICATION_REQUIRED=...

Property File:

mockserver.controlPlaneBasicAuthenticationRequired=...

Example:

-Dmockserver.controlPlaneBasicAuthenticationRequired="true"

The users allowed to use the control plane with Basic authentication, each as username:passwordHash or username:passwordHash:scopes, separated by ; or new lines.

Plain text passwords are refused. The password must be given as a hash in one of these formats:

  • bcrypt ($2y$, $2b$, $2a$) — for example from htpasswd -nbB -C 12 admin 'my password', whose output line can be used as it is
  • argon2 ($argon2id$, $argon2i$, $argon2d$) — for example from echo -n 'my password' | argon2 "$(openssl rand -hex 8)" -id -e
  • PBKDF2 ($pbkdf2-sha256$, $pbkdf2-sha512$) — for example from Python's passlib: pbkdf2_sha256.hash('my password'). PBKDF2 needs no extra libraries, so use it when MockServer runs with BouncyCastle FIPS instead of the standard BouncyCastle library.

The optional scopes (separated by spaces or commas) give the user roles when control plane authorization is enabled: they are mapped to roles by controlPlaneScopeMapping, just like OIDC scopes.

Work factors must be sensible: bcrypt cost 4 to 16, PBKDF2 10,000 to 10,000,000 iterations, and argon2 at most 256 MiB of memory, 16 passes and 16 lanes, because every password check runs while requests wait. MockServer warns at startup about a hash below current OWASP guidance (bcrypt cost 10, PBKDF2-SHA256 600,000 iterations, argon2id 19 MiB with 2 passes) — htpasswd -B defaults to cost 5, so pass -C 12.

MockServer refuses to start if Basic authentication is enabled and no users are configured, or any entry is not in one of these formats or outside these limits. The value is hidden in the printed configuration and is never returned by GET /mockserver/configuration. It is fixed at startup.

Type: string Default: ""

Example:

MOCKSERVER_CONTROL_PLANE_BASIC_AUTHENTICATION_CREDENTIALS='admin:$2y$12$Qv0yN...:platform-admins;ci:$2y$12$9fT2a...:qa-team'

Path to a file of control plane Basic authentication users, one username:passwordHash[:scopes] per line, in the same formats as controlPlaneBasicAuthenticationCredentials. This is the format htpasswd -B writes, so a file it maintains can be used directly. Blank lines and lines starting with # are ignored. Users from the file and from controlPlaneBasicAuthenticationCredentials are combined.

The file holds password hashes, so make it readable only by the user MockServer runs as. It is read when the server starts, and again whenever another control plane authentication setting changes while the server runs.

For tests only. Accept control plane Basic credentials sent over plain HTTP. Without TLS the password crosses the network in a form anyone on the path can decode, so never enable this where the network is shared. Behind a proxy that terminates TLS, have the proxy connect to MockServer over HTTPS instead. MockServer logs a warning at startup when this is enabled. It is fixed at startup.
