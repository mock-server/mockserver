CORS Configuration:

 

Which web pages can use MockServer's own API. MockServer's own API (every /mockserver/... path, including MCP and metrics), the dashboard's live log and the callback WebSocket only answer browser pages they trust. This is set by controlPlaneCorsAllowOrigin. Left blank (the default), a page is trusted when it is:

  • on localhost, 127.0.0.1 or [::1], on any port, over http or https (for example a front-end dev server on http://localhost:3000 or a browser test), or
  • served by the same MockServer, at the same host and port, such as the dashboard, when you reach MockServer by localhost, an IP address, a single-word name such as a Docker, Compose or Kubernetes short service name (http://mockserver:1080), a Kubernetes service name ending in .svc or .svc.cluster.local, or a name ending in .internal (such as host.docker.internal or an AWS ec2.internal name).

A page MockServer serves at any other name, for example https://mockserver.example.com, is not trusted unless you list it in controlPlaneCorsAllowOrigin, or its name ends in a suffix listed in controlPlaneTrustedHostSuffixes. This is so even when controlPlaneCorsAllowOrigin already lists other origins. This is what stops a DNS-rebinding attack from an ordinary malicious web site, which points its own name at MockServer so that its page looks like one MockServer served.

A request to MockServer's own API, or a WebSocket connection, from any other page is refused with 403, whatever its method, before MockServer handles it and before any expectation can answer it; its preflight gets no Access-Control-Allow-* headers. That includes Origin: null, which sandboxed iframes and pages opened from a file send. Tools that are not browsers (curl, the client libraries, your tests' HTTP clients) send no Origin and are not affected.

If a page on another host needs to call MockServer's API, for example a front-end served from https://app.example.com, or the dashboard pointed at a MockServer on another host, set controlPlaneCorsAllowOrigin on that MockServer to the page's origin. The same applies when MockServer sits behind a reverse proxy or Kubernetes ingress that changes the Host header: the dashboard then looks like a page on another host, so set it to the address you open the dashboard at, for example https://mockserver.example.com.

Mocked and proxied responses are separate: they only get CORS headers when enableCORSForAllResponses is on, and then follow corsAllowOrigin, which no longer affects MockServer's own API. A CORS preflight for a request MockServer's own API serves (any /mockserver/... path, or a legacy path such as /reset or /graphql with a method the API serves there) is answered by MockServer under its own rule, not by an expectation. An unmatched preflight for another method on such a legacy path, for example POST /graphql to a mocked GraphQL API, allows only the requested method.

This check stops other web sites using MockServer's API or WebSockets through a visitor's browser, including through DNS rebinding. It does not stop:

  • an attacker who controls how your machine looks up names (a hostile Wi-Fi network, a spoofing machine on the same local network, or someone who can change your cluster's DNS), who can still rebind any trusted name except an IP address or localhost;
  • a rebinding attack on a public name you have chosen to trust;
  • a site visited in a browser that uses MockServer as its proxy, because the page is then same-origin with MockServer.

If any of these applies, for example when you run MockServer on a laptop on public Wi-Fi, or untrusted pages may run in a browser that can reach MockServer, also turn on control-plane authentication.

Answer CORS preflight (OPTIONS) requests that no expectation matches, for every path, using the corsAllowOrigin policy. In practice it is always on once a preflight has been received: the first CORS preflight MockServer answers itself turns it on. MockServer's own API answers preflights under its own rule (see which web pages can use MockServer's own API) whatever this is set to.

The value used for CORS in the access-control-allow-origin header of mocked and proxied responses (when enableCORSForAllResponses is on). When blank, the request's origin is sent back. It does not affect MockServer's own API, the dashboard or the callback WebSocket; use controlPlaneCorsAllowOrigin for those.

Note: To ensure access-control-allow-credentials works correctly, when corsAllowCredentials is true the CORS header access-control-allow-origin will set its value using the origin header on requests instead of corsAllowOrigin property.

Type: string Default: ""

Java Code:

ConfigurationProperties.corsAllowOrigin(String corsAllowOrigin)

System Property:

-Dmockserver.corsAllowOrigin=...

Environment Variable:

MOCKSERVER_CORS_ALLOW_ORIGIN=...

Property File:

mockserver.corsAllowOrigin=...

Example:

-Dmockserver.corsAllowOrigin="*"

The browser origins allowed to use MockServer's own API (every /mockserver/... path), the dashboard's live log and the callback WebSocket, as a comma-separated list such as https://app.example.com, http://ci-browser:8080. An allowed page gets its origin sent back in access-control-allow-origin; any other page's requests and WebSocket connections are refused with 403, and its preflights get no CORS headers.

When blank (the default), pages on localhost, 127.0.0.1 or [::1] (http or https, any port) are allowed. Pages MockServer serves itself, such as the dashboard, are also allowed when MockServer is reached by localhost, an IP address, a single-word name, a name ending in .svc, .svc.cluster.local or .internal, or a controlPlaneTrustedHostSuffixes entry, whatever this is set to (see controlPlaneTrustedHostSuffixes); to open the dashboard at any other name, list its origin here, for example https://mockserver.example.com. * allows every web site to read from and change MockServer through a visitor's browser, so only use it when nothing sensitive can be reached. See which web pages can use MockServer's own API.

It can only be set when MockServer starts: PUT /mockserver/configuration ignores it and logs a warning, so a request to the control plane cannot widen it.

Type: string Default: ""

Extra host-name endings, as a comma-separated list such as corp.example, k8s.example, at which a page MockServer serves itself, such as the dashboard, may use MockServer's own API and WebSockets. Use it when your Kubernetes cluster uses a custom domain instead of cluster.local, or when you reach MockServer by a private name such as mockserver.corp.example.

Without it, a page MockServer serves is trusted only when MockServer is reached by localhost, an IP address, a single-word name (a Docker, Compose or Kubernetes short service name) or a name ending in .svc, .svc.cluster.local or .internal. A suffix covers names below it (mockserver.corp.example), not the suffix itself; corp.example, .corp.example and *.corp.example mean the same. A public suffix, under which anyone can register a name, such as com, co.uk or github.io, is rejected: it trusts nothing and MockServer logs an error at startup. MockServer also logs a warning for an entry it cannot use. Only list names public DNS cannot resolve: a malicious site that can make a listed name point at MockServer can use MockServer's API through a visitor's browser (DNS rebinding). Even a private name can be rebound by someone who controls your network's name lookups, so use control-plane authentication where that matters.

It can only be set when MockServer starts: PUT /mockserver/configuration ignores it and logs a warning.

Type: string Default: ""

The value used for CORS in the access-control-allow-methods header.

The property default is blank. When blank, MockServer does not send an empty header; it applies a built-in fallback of CONNECT, DELETE, GET, HEAD, OPTIONS, POST, PUT, PATCH, TRACE so the control-plane API and dashboard work cross-origin out of the box. Set this property only if you need a narrower method list.

Type: string Default: "" (effective default: CONNECT, DELETE, GET, HEAD, OPTIONS, POST, PUT, PATCH, TRACE)

Default value used for CORS in the access-control-allow-headers and access-control-expose-headers headers.

In addition to this default value any headers specified in the request header access-control-request-headers also get added to access-control-allow-headers and access-control-expose-headers headers in a CORS response.

The property default is blank. When blank and the preflight request carries no access-control-request-headers header, MockServer applies a built-in fallback of Allow, Content-Encoding, Content-Length, Content-Type, ETag, Expires, Last-Modified, Location, Server, Vary, Authorization rather than sending an empty header. When blank and the preflight does carry access-control-request-headers, MockServer instead echoes back exactly the headers the browser asked to send. Setting it makes the listed headers always allowed; any headers a preflight requests are still added to them.

Type: string Default: "" (effective default: Allow, Content-Encoding, Content-Length, Content-Type, ETag, Expires, Last-Modified, Location, Server, Vary, Authorization)

The value, in seconds, used for CORS in the access-control-max-age header, which tells the browser how long it may cache a CORS preflight (OPTIONS) response before sending another one. Raise it to reduce the number of preflight requests a browser-based client sends against a long-running MockServer instance; the default of 0 tells the browser not to cache preflights at all.
